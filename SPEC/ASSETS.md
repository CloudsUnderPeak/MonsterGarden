# 怪物圖片規格與匯入

## 原圖收件匣

新增圖片放在根目錄的 `monster-inbox/`，可使用子資料夾，原檔名不必整理。此目錄的圖片由 Git 忽略；只有保留空目錄的 `.gitkeep` 會納入版本管理。

支援 PNG / AVIF，副檔名不分大小寫。原圖保留原始檔名和內容，不修改、刪除或另行轉檔。

## 正式圖片命名

網站只載入 `assets/monsters/` 的正式副本，命名格式為：

```text
monster-001.avif
monster-002.avif
monster-012.png
```

規則是 `monster-` 加至少三位數流水號，副檔名使用原始格式的小寫名稱。PNG 不會只改副檔名假裝成 AVIF。

後續匯入接續最大流水號。既有 ID 不因排序、新增或刪除而變動，不補空號，也不以新圖片覆寫舊 ID。

## 比對與匯入流程

由代理依 `AGENTS.md` 執行維護：

1. 遞迴檢查收件匣，與正式檔案及 `SPEC/MONSTER_ASSETS.json` 比對 SHA-256。
2. 同內容即使換檔名也略過；同檔名但不同內容視為新圖。不同格式或重新壓縮後的檔案可能有不同雜湊，不宣稱能偵測所有視覺相似圖片。
3. 新圖分配下一個 ID，複製到正式目錄，原圖繼續留在收件匣。
4. 更新匯入紀錄與 `src/config/monsters.js`，確認正式圖片沒有漏列、重複或失效路徑。

若圖片仍被直接放到正式目錄，先保留原圖到收件匣，再整理正式檔名。原圖檔名發生衝突時，使用不同子資料夾保存，不覆寫。

`SPEC/MONSTER_ASSETS.json` 記錄 ID、正式路徑、SHA-256 與原始檔名，僅供維護追蹤，網站不讀取這份文件。即使正式圖片被刪除，仍保留歷史紀錄，避免重新分配曾用過的編號。

## 網站檔名清單

網站維持明確的 `Garden.monsterPaths` 清單，不增加掃描啟動器、產生清單的常駐程式或後端。例如：

```js
Garden.monsterPaths = Object.freeze([
  'assets/monsters/monster-001.avif',
  'assets/monsters/monster-002.avif',
]);
```

路徑相對於 `index.html`，區分大小寫，使用 `/`。純靜態瀏覽器不會自行列出本機或網站的資料夾內容；圖片整理和清單維護由代理處理。

## 圖片處理與朝向

建議使用透明背景、角色朝右的圖片。網站維持比例，裁掉透明邊界，不修改原檔。AVIF 需要瀏覽器解碼支援。部分瀏覽器在 `file://` 下限制讀取像素時，會使用原始圖片邊界。全透明或無法解碼的圖片會跳過，畫面僅在載入異常或沒有圖片時顯示簡短提示。

原圖若面向左方，將正式 ID（不含副檔名，例如 `monster-004`）加入 `src/config/monsters.js` 的 `Garden.leftFacingMonsters`。繪製時會與移動方向一起計算水平翻轉，拖曳和命中判斷共用同一姿勢。重新命名既有圖片時也要同步保留這些設定。
